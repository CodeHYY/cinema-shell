影视仓 / OK影视 打不开、配置取得失败怎么办？

提示「配置取得失败」「加载失败」，或者首页只剩一片空白，大多数时候不是 App 坏了，而是它去下载你填的「配置地址」时没拿到文件。下面按出现概率从高到低排查。

先说明本站身份：本站是 星河影院 / 赤焰影院 等 Android 影视客户端的下载页。我们的 App 不内置片源，内容来自第三方公开站点；含第三方广告 SDK，靠广告变现，详见隐私政策。下面的教程对任何同类软件都适用，是否装我们的 App 由你决定。

先弄懂：为什么会「配置取得失败」

影视仓、OK影视（FongMi 系）、TVBox 这一类软件本身只是一个播放壳，不带任何片源。首页的分类、搜索、线路，都来自你在「设置 → 配置地址（或点播）」里填的一个 JSON 配置文件。每次启动或切换配置，App 都要先把这个文件下载回来；下载不到，就会提示配置取得失败，或者直接空白。

所以排查的思路只有一个：这个地址，此刻这台设备能不能取到内容？

第 1 步：确认地址本身还活着

最常见的原因是地址失效——维护者停更、域名到期、仓库被删。用手机或电脑浏览器打开同一个地址：

  • 能看到一大段 JSON 文本（有的接口是加密后的乱码文本，也算正常）：服务器在线，问题在设备这一侧，继续下面的步骤。
  • 404、拒绝连接、一直转圈：地址已失效，换一个可用的地址即可，不用折腾设备。

注意：配置地址是填进 App 里用的，不是让你当网页看的；不同设备对中文域名的支持也不一样，中文域名取不到时，改用手机推送（见第 6 步）或换成英文域名的地址。

第 2 步：托管在 GitHub 的地址，换成国内更稳的访问方式

很多配置托管在 GitHub 的 raw 链接上，在国内常常间歇性打不开。同一个文件可以换成 jsDelivr 的形式访问，格式为：

https://cdn.jsdelivr.net/gh/用户名/仓库名@分支名/文件路径

jsDelivr 有缓存，更新会慢一些；也有社区维护的 GitHub 加速代理，但这类代理本身也会失效，不要只依赖一个。

第 3 步：检查网络、DNS 和系统时间

  • DNS：把电视盒子（或路由器）的 DNS 手动改成 223.5.5.5 或 119.29.29.29，再重试；运营商默认 DNS 有时解析不到境外 CDN。
  • 代理 / VPN：电视或路由器上开着代理的话先关掉试一次。
  • 系统时间：老盒子断电久了时间会回到 1970 或 2018 年，HTTPS 证书校验会直接失败，表现就是什么都加载不了。到系统设置里打开「自动获取网络时间」。

第 4 步：检查是不是填错了

地址末尾多了空格、把 https 写成了 http、复制时带上了说明文字，都会取不到。用遥控器输入太容易出错，建议用手机推送：电视和手机连同一个 Wi-Fi，在电视端打开推送 / 网页遥控入口，手机扫码或访问页面，把地址粘贴过去再推送，电视端确认即可。

第 5 步：清缓存、更新 App

先在 App 设置或首页里找「清除缓存」，没有的话到系统「应用信息」里点清除缓存。先不要点「清除数据」，那会把你填过的地址和历史记录一起删掉。再试一次不行，就把 App 更新到较新的版本——旧版对新格式配置、新的爬虫脚本支持不好，会出现配置能下载但站点全部失败的情况。

第 6 步：配置能下载，但站点还是空的

这是另一类问题：配置文件取到了，但里面的各个站点（爬虫）已失效。表现为首页有分类，点进去没有内容，或搜索全无结果。处理办法：换一个维护更勤的配置、在首页切换站点或线路，不要只留一条。

第 7 步：还是不行，把变量一个个拆开

换一个全新的地址试；换手机热点试（排除家里网络）；换一台设备装同一个 App 试。这三个结果能把问题定位到「地址」「网络」还是「设备」。另外，配置里可以带爬虫代码，会在你的设备上运行，只填你信得过的来源。

不想折腾配置地址？

我们的 星河影院、赤焰影院 打开就能检索，没有「填配置地址」这一步，也就没有「配置取得失败」。代价是：它只做影视检索与播放（换线路、弹幕、续播），没有 TVBox 那种导入自定义配置的能力；片源是第三方公开站点，可能随时变化；含广告 SDK。想对比各家适用场景，看这篇对比；还没学会填配置的，看点播源配置教程。安装方法见安装指南。

常见问题

配置取得失败是 App 的问题吗？

多数不是。App 只是去下载你填的配置地址，下载失败就会报错。先确认地址在浏览器里能打开。

为什么同一个地址，手机能用电视不能用？

常见原因是电视盒子的 DNS 解析、系统时间错误，或设备对中文域名支持不好。改 DNS、校准时间、用手机推送。

清除数据会怎样？

会删掉已填的配置地址和观看历史，需要重新填写；排查时先只清缓存。

我必须一直找新接口吗？

用这类软件基本如此，地址会随维护者变动而失效。多备几个来源，比依赖一个更稳。
